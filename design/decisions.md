# 设计决策

本文件记录跨客户端设计知识的组织与演进取舍。状态针对所列范围，不能推出产品视觉已批准。技术执行、协议与生命周期决策继续归 [系统架构](../docs/design/architecture.md)及既有 ADR。

## D-001 共享设计知识独立于 GUI

本轮文档组织采用。2026-10-22。

GUI、CLI、TUI 与 Web 需要共同理解设计意图。共享入口置于根目录 `design/`，GUI 的组件、布局、平台行为和准入继续放在原所有者。先建立设计地图并提炼共享知识，逐条迁移经核对的规则，原文改为引用。代价是暂时需要区分共享知识与已有平台材料。复核条件是同一规则出现两个可编辑定义，或新客户端仍必须读取 GUI 专属合同才能完成普通设计任务。

## D-002 共享语义先于统一数值与实现

架构建议，待具体迁移验证。

图形界面、终端与机器输出共享用户意图和状态含义。它们保留适合本端的交互、几何和能力映射。当前已有不同的生产主题源，直接复制 GUI 数值会掩盖差异。先建立 [Token 映射](tokens.md)，再按实际消费者选择共享默认值子集。复核条件是同一默认值已被多个消费者确认，并需要共同版本和漂移检查。

## D-003 先设计完整候选，再迁移真实路径

架构建议，待候选与产品验收。

整体候选同时呈现工作区、对话、资源与设置，先检验共同视觉与交互语言。生产实现按可独立验收的用户路径推进，迁移调用方并删除替代路径。候选中的模拟不替代真实客户端和包的验收。日常维护无需重做独立重建，规则传递能力在冻结迁移题中单独评价。细节见[架构草案](architecture.md)。
