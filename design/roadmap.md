# 设计系统建设顺序与缺口

AReaL 已有生产控件、GUI 目录、状态合同和开发预览。当前共享目录已有原则、基础、内容、人机关系、模式、组件、产品和决策。首条文档纵切连接术语、反馈措辞、基础角色、工作台和就近组件合同。[完整工作台候选](products/workbench/candidate.md)将这些选择组合成一条可操作的本地任务路径，供整体评价。提交、过程、审批到结果的首条视觉切片已接入生产组件，提供隔离真实 GUI 体验。任务、外观、资源三条切片已有真实 GUI 路径证据。有限 Base 已冻结，并完成固定输入的独立复用与归因；下表保留后续缺口。

2026 年 10 月 23 日，用户首轮体验反馈为“目前看没什么问题，和现在的基准版本差不多”。当前保留基准视觉方向。后续资源查看与返回、有限 Base 冻结、独立复用题及另一真实任务保留检查已完成。该反馈只对应已体验范围，不表示全主题、字号、状态或整个 Base 已验收。

## 本轮已完成

[Base beta](../clients/gui/design-system/base.md)固定有限成员、状态、来源、合同、证据与兼容规则。[交付物核对独立结果](components/reuse-result.md)记录实际冻结提交、实现输入隔离、操作验收与归因。新页面复用已有组件和 Token，无页面 CSS；真实资源返回保留场景再次通过。运行边界与用户视觉评价分别记录，不将这一次最小闭环扩大为整个系统完成。

当前文案是采用建议，工作台包含设计要求、源码映射与本地可操作候选，就近合同也不等于生产行为验收。文档入口和已有示例形成首条阅读路径，首条任务切片已沿真实 Electron、Core 和 Runtime 验证，模型事件由本地确定性服务提供。其他路径、真实供应商和安装包仍需分别验证。GUI 的 [Base beta](../clients/gui/design-system/base.md)已按有限范围冻结；P-RESOURCES、完整对话、完整 SidePane 与其他平台仍未准入。现有目录主要检查引用与声明，不能证明实际 JSX 采用了对应组件，也不能代替视觉或平台验收。

## 先形成完整候选，再收敛实现

1. 固定一个完整设计版本。以提交任务、观察工具、处理决定、查看资源和返回阅读为主路径，同时安排一次外观设置修改。列出必要的失败与未知结果，固定明暗、字号和宽窄条件。交付可操作候选、关键状态和设计决定，先评价整体体验。
2. 明确首批基础角色。结合 GUI 候选决定文字、表面、反馈、间距、形状和图标的使用关系。输出角色到当前 GUI 实现的映射，明确默认值与动态偏好边界，记录未来 Web 复用时需要适配的原生能力。
3. 收敛一组 Token 与组件。先迁移候选实际使用的一组角色及 Button、Select、Switch、Feedback 等控件。共享默认值只有一处可编辑源，平台输出可重复生成并检查漂移。用户偏好保留运行时输入。迁移调用方后删除被替代定义，不同时维护两套数值。
4. 核对文档与真实示例。首批就近合同和设计内容已进入文档目录。复用现有 GUI 预览核对组件状态、组合、主题、字号和平台限制，设计理由归 `design/`，类型提供接口事实。下一步候选是核对目录声明与实际导出，以及从同一元数据提供检索，不另写一套 Props 或组件名单。
5. 迁移首条 GUI 生产路径并复验。绑定原有业务控制器，分别检验权威结果、草稿与身份、阅读与焦点。完成后用另一种 GUI 任务检查设计规则，再决定扩大 Base 准入。后续 Web 实际接入时选取对应任务独立验收，不阻塞当前 GUI 交付。

共享默认值的生成格式在第二步确定。DTCG 可作为候选，但不为采用某种格式提前搬运所有数值。独立发布组件包、独立文档站和专用 Agent Skill 都不是首轮前提。先让现有生产组件、文档和示例形成可复验的最小闭环，有独立消费者或明确检索需求后再扩展。

验证证据的职责边界统一见[架构](architecture.md#验证边界)。以下条件持续用于后续产品建设，已完成范围以 Base 与独立结果为准。文档归档不自动满足运行条件。

## 首轮完成条件

- 同一候选覆盖工作区、对话、资源、设置及所选异常路径，整体视觉决定可审查。
- 所选 Token 和组件有明确所有者、真实消费者、状态合同与验证位置。
- 文档中的示例使用生产实现，目录生成与漂移检查通过。
- 行为、视觉、原生平台与安装包分别报告实际覆盖，未覆盖项保留。
- 原有调用方完成迁移，被替代定义删除，新增任务能复用同一设计选择。
