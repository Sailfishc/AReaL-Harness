# 设计基础

AReaL 是围绕任务执行与结果阅读的工作台。基础语言用清楚的内容层级、有限强调和稳定布局支持持续工作。具体值由 [Token 与平台映射](tokens.md)指向的生产源维护，本目录维护使用理由与跨端关系。

## 内容层级与表面

主内容承载当前任务，导航、过程和辅助信息降低强调。视觉层次来自内容顺序、间距及表面关系。一个分组表达一个功能关系，不给每段文字和状态再增加独立卡片、重阴影或装饰渐变。终端用字符层级和已有主题表达同样关系，不要求复制图形表面。

## 文字、空间与形状

正文、控件、说明和诊断各有明确用途。代码与路径保留适合核对的等宽表达。字号或内容增长时先重排，不能靠缩字、固定行高或无提示裁切隐藏必要信息。共同角色进入 Token，独有几何由本端组件拥有。

GUI 的圆角与控件密度沿本端角色。TUI 使用终端字符单元及自身布局；机器输出按协议组织。跨端共享含义，实际字体、边框和命中范围分别核对。

## 图标与资产

沿用 AReaL 已有应用、供应商及界面资产。图标用于帮助识别操作或对象，文字操作不机械附加装饰图标。纯图标操作需要可访问名称，提示文字补充含义。GUI 的具体图形与尺寸见 [interfaceIcons](../../clients/gui/renderer/src/interfaceIcons.tsx)，终端文字和字符表达遵循本端能力。

## 状态、动效与可达性

状态与操作含义不能只靠颜色、动画或悬停传递。减弱动态效果或缺少颜色时，必要信息和动作仍可理解。动效解释反馈、空间关系或连续性，起止状态、可中断方式及减少动态效果后的结果都需要明确。

控件保留所属平台的标签、键盘与焦点语义。主标签用用户任务命名，诊断路径和技术标识在需要核对的详情中提供。具体状态展示见[反馈与恢复](../patterns/feedback-and-recovery.md)，人的决定与执行关系见[人机协作](../people-and-agents/README.md)。
