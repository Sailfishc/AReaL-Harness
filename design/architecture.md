# AReaL 共享设计系统架构草案

状态为设计草案。[Design Docs](README.md)独立组织共享知识，各客户端实现相应表达。GUI 先完成一个覆盖工作区、对话、资源和设置的新版候选，再按完整用户路径迁入生产。用户得到连贯的操作体验，维护者得到可定位、可复用和可复验的设计系统。本提案不改变现有 GUI Base 准入，也不代表新版视觉已获验收。

源码事实核对于 2026-10-22，基线为 `aefd8f9f`。后续改变相关所有者时重新核对，不能将本次观察视作永久保证。

现有[GUI 实现架构](../clients/gui/design-system/architecture.md)已经具备职责分层、目录、真实组件预览和验证入口。下一步将其中跨端成立的设计知识提升到共享所有者，再通过真实路径检验各端表达。文档迁出 GUI 不要求同时抽组件包、建设全量 Token 编译器或页面 DSL。

## 共享知识独立于客户端实现

根目录 `design/` 是设计知识入口。`docs/design/` 继续解释系统执行机制，`clients/*` 拥有具体客户端实现与平台准入。设计知识的归属按规则含义决定，不能按它最初出现在哪个客户端决定。

| 职责 | 共享设计知识 | 客户端拥有的部分 |
| --- | --- | --- |
| 原则与意图 | [原则](principles.md)、[意图及模式](intents.md)描述理由与用户结果 | 适用的输入方式、导航、反馈和内容组织 |
| 基础角色 | [Token 语义](tokens.md)描述角色，指向当前来源及候选映射 | CSS、终端颜色和字符布局，平台能力、用户偏好及实际数值 |
| 控件与组合 | 跨端成立的选择依据及必须保留的结果 | React 控件、Ratatui 选择器、Web 组件和 CLI 输出实现 |
| 产品绑定 | 显示事实与用户意图的边界 | 各端控制器、服务接线及已有协议，不增加共享执行循环 |
| 设计决策 | [决策](decisions.md)记录产品取舍与重审条件 | 本端例外、原始取证、运行和发布验证 |

跨端共用设计含义，当前实现不必共用语言、渲染器或依赖包。共享文档不依赖 GUI 文档才能定义一条共同原则。它可以将 GUI 作为一个实现示例，并列出其他平台尚未完成的适配。

当前 [TUI 主题](../clients/tui/src/theme.rs)已经拥有语义角色、无色与终端颜色转换；[本地 Web](../clients/web/style.css)有独立 CSS，[CLI](../clients/cli/src/run.rs)拥有文字及机器输出路径。这些真实消费者说明共享入口应高于 GUI，但不能据此宣称相同颜色或组件已经通用。Remote Web 与本地 Web 也分别登记。

先把共用原则、意图、Token 地图和设计决策放入本目录。既有 GUI 规则逐项分类，共享部分迁出后在旧位置引用，桌面尺寸、控件 API、窗口和平台证据留在 GUI。不要批量移动整个目录并把桌面规则自动提升为全局规则。

当前 `clients/gui/design-system/registry.json` 是 GUI 组件索引，GUI 的 I-* 和 P-* 仍由原规则定义。根地图不把它包装成跨语言的全局组件清单。后续只有实际消费者需要跨端机器检索时，才增加共享语义 ID 及各端绑定，平台目录依旧拥有真实导出。

## GUI 新版候选如何检验整体体验

候选版本以“持续完成一个任务”为主线。导航负责位置，对话负责要求、执行与结果，资源区域负责深入查看，设置负责持久偏好。四者共用文字层级、空间节奏、状态语义和焦点规则。

| 区域 | 建议的新版职责 | 必须一起设计的状态 |
| --- | --- | --- |
| 工作区 | 区分项目、会话和当前资源。主任务保持可定位，辅助内容可关闭并返回 | 空项目、新草稿、首次受理、切换任务、恢复连接 |
| 对话 | 按轮次组织要求、过程与回答。过程默认收敛，用户展开选择可保留。Composer 显示当前可执行动作 | 流式更新、工具执行、审批、停止、断线、受理结果未知 |
| 资源 | 复用文件、Diff、上下文等实际资源入口。打开与返回保留所属任务、阅读位置和键盘焦点 | 加载、空内容、无权限、失效资源、关闭、会话身份迁移 |
| 设置 | 用一致分组和字段结构说明作用范围。外观修改即时反馈，并保留合法用户选择 | 长标签、非法值、恢复默认、系统主题变化、字号增长 |

这些区域先出现在同一个可运行候选中。候选应能走完“新建草稿、提交、观察工具、处理审批未知、打开资源、返回继续阅读”，并包含一次设置修改。这样才能发现侧栏密度、对话宽度、资源空间和字体尺度之间的冲突。单独完善控件页无法证明这个结果。

视觉方向围绕 AReaL 任务工作台展开，沿用已有应用、供应商图标和[公共图标所有者](../clients/gui/renderer/src/interfaceIcons.tsx)。建议用中性表面区分阅读层级，强调色表达选择和主要动作，状态色表达执行结果。具体色值和尺寸先留在现有生产链，通过候选比较后再采纳。

## GUI 候选的实现所有者

下表划分职责，不要求新增对应目录或包。运行时由产品绑定组合、组合使用通用控件、控件消费基础角色。通用控件不反向依赖 AReaL 组合。设计理由、目录与证据属于开发期输入，不进入执行链。

| 责任 | 当前所有者与建议变化 |
| --- | --- |
| 设计意图 | 保留 [foundations](../clients/gui/design-system/foundations.md)、[patterns](../clients/gui/design-system/patterns.md)、[interactions](../clients/gui/design-system/interactions.md) 和治理文档。规则旁记录适用条件与理由，跨模块取舍回到既有架构决策文档 |
| 基础角色 | [styles.css](../clients/gui/renderer/src/styles.css)、[applicationSettings](../clients/gui/renderer/src/settings/applicationSettings.ts)、[applicationPreferences](../clients/gui/renderer/src/settings/applicationPreferences.ts) 和 [Main](../clients/gui/app/src/core/main.cjs) 各保留真实职责。先明确默认、用户偏好、宿主题、CSS 应用的优先级 |
| 通用控件 | 复用 [components/ui](../clients/gui/renderer/src/components/ui)。控件拥有变体、键盘、焦点和无障碍语义，不读取业务服务 |
| AReaL 组合 | 从 [SettingsPageParts](../clients/gui/renderer/src/settings/SettingsPageParts.tsx)、[ComposerSurface](../clients/gui/renderer/src/prompt-editor/ComposerSurface.tsx)、[DecisionCard](../clients/gui/renderer/src/DecisionCard.tsx) 和 [Messages](../clients/gui/renderer/src/Messages.tsx) 演进。组合拥有布局与呈现合同，接受状态和动作 |
| 产品绑定 | [App](../clients/gui/renderer/src/App.tsx)、[Composer](../clients/gui/renderer/src/Composer.tsx)、[RemoteWorkbench](../clients/gui/renderer/src/remote/RemoteWorkbench.tsx) 及原有控制器负责业务映射。受理、权限、停止与历史事实沿原有 Core、Desktop 和 Workbench 所有权判断 |
| 开发入口 | [registry](../clients/gui/design-system/registry.json) 保留结构索引权威。组件相邻文档拥有用途和行为说明，TypeScript 拥有 props，fixture 使用真实组件。目录、文档站与 Agent 索引均读取这些源 |

同一事实只维护一份。组件说明可以相邻存放，但不再复制 registry 中的 ID 或路径为另一份可编辑 front matter。组件成熟度若需要登记，也只由 registry 维护。现有[生成器](../clients/gui/scripts/design-system-catalog.mjs)继续生成目录。先扩展现有入口需要的字段，再考虑文档站。预览仍由[独立入口](../clients/gui/renderer/src/design-system/main.tsx)构建，不连接真实业务或进入生产路由。

“一个角色一个所有者”不等于把所有数值装入一个文件。当前 App 另存 `areal-gui:font-size`，外观偏好还有独立的字体和内容字号链。Main 返回的主题 CSS 不能视作已被 App 完整消费，[RemoteWorkbench](../clients/gui/renderer/src/remote/RemoteWorkbench.tsx)也没有与桌面共享全部选择。建议迁移时先收敛同一偏好的持久化和应用所有者，再提供桌面与浏览器所需的窄适配。默认保持各客户端本地偏好，不新增跨设备同步。同步范围属于产品选择，不能从源码推导。

## 取舍与生产迁移

| 方案 | 收益 | 代价与建议 |
| --- | --- | --- |
| 只修文档和目录 | 修改少 | 无法证明完整新版体验，不足以完成目标 |
| 一次替换为独立设计包 | 发布边界整齐 | 同时迁移主题、偏好、控件与业务绑定，风险集中。暂不采用 |
| 完整候选先行，再迁移完整路径 | 可先评价整体，再逐步证明真实行为 | 需维护明确的候选与生产证据边界。推荐采用 |

先固定候选的页面关系、主路径、失败分支和代表条件，再完善真实组件 fixture。下一份具体交付是可操作的完整候选、对应的状态合同和所有者映射。需要权威回执的状态用明确 fixture 演示，并标明模拟条件。

| 单元 | 可审查的产物 | 进入下一单元的条件 |
| --- | --- | --- |
| 整体设计 | 四个区域的共同视觉语言、主路径、异常路径和既有资产映射 | 同一候选可走通主路径，明确哪些决定是目标、哪些来自生产 |
| 基础与合同 | 角色来源表、必要组件变体、组合合同与代表状态 fixture | 每个角色有唯一修改位置，偏好与平台差异有明确范围，不出现第二份数值源 |
| 首条生产路径 | 原控制器接线的真实提交、工具、审批与资源往返 | 行为、阅读、焦点和 UNKNOWN 分别有对应证据，迁完本单元调用方并删除替代路径 |
| 独立迁移题 | 冻结输入后新增的另一种任务及独立评判结果 | 能复用共享规则，发现偏差可归因到具体所有者，失败和缺口保留 |

合同沿用现有 `surfaces/` 的稳定 ID、意图、规则、组件、状态与条件。只在首条路径确有需要时补充场景和反例引用。场景描述初态、用户动作、输入事实及可观察断言，不能直接设置预期的展开、成功或跟随标志。用于验证规则传递的冻结题包与评判材料分开，日常产品开发不强制采用独立重建流程。

生产迁移从上述首条路径开始。一个单元同时迁移关联的 Composer、过程展示、审批卡和资源返回规则，避免半条路径使用两套状态语义。主题角色的调整覆盖候选全部区域，并用代表设置页面检查偏好效果。后续再按工作区恢复、资源深入操作和设置分组推进。每个单元迁移实际调用方并删除被替代路径，仅为已确认消费者保留必要兼容。

GUI 单元采用以下四类证据。跨端复用另选 TUI 或本地 Web 的同意图场景，分别核对输入、事实和结果，不能拿 GUI fixture 证明另一客户端通过。非交互 CLI 按已有输出契约验收，不增加其不支持的审批或资源面板功能。

| 证据 | 能证明什么 | 不能替代什么 |
| --- | --- | --- |
| 代码与静态检查 | 类型、边界、索引和生成一致性。现有 [changes](../clients/gui/scripts/design-system-changes.mjs) 已含 Git 增量 CSS 与静态 JSX 扫描 | 任意动态样式、重复实现、真实导出与声明的匹配，以及实际视觉依从 |
| fixture | 同源码的明暗、字号、宽窄、键盘和 reduced motion 代表状态 | 真实回执、持久化和资源生命周期 |
| 隔离 Electron 路径 | 焦点、滚动、异步归属、UNKNOWN 保留、打开资源与返回。原生视图另取证 | 未执行的真实供应商、设备或平台 |
| 安装包 | 打包后的资源、启动和桌面集成 | 仅源码通过时不得宣称通过。后续 macOS 发布仍需签名、公证、staple 与 Gatekeeper 证据 |

文档 schema 版本只描述格式。输入冻结只固定材料。组件 API 成熟度描述接口承诺。Base 准入表示规则、实现与限定条件已验证。单次证据只说明该环境下的结果。这些状态分别记录，不能由一个“v1”标签互相推出。

本提案完成条件是整体候选方向、真实所有者、首条路径和验收边界已明确。后续迁移单元在调用方迁完、替代路径删除、相关检查与运行证据齐备、owned diff 审阅后结束。未覆盖条件明确留下，继续演进时再按实际失败归因。每轮新增题目应检查共享规则是否有效，避免只修到某张参考图相似。

具体建设缺口、产物与顺序见[建设计划](roadmap.md)。
